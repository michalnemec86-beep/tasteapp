# Pivník - obnova a předání projektu

Stav: 2. 10. 2026. Produkční commit: 65ed1f0f6938ae4a87d53623e2123485c52812e6.

## A. Znovu spustit aplikaci se současným backendem

1. Zachovat přístup k GitHubu, Vercelu a projektu Supabase
   `nsnvryyocwzfwxiwhqca`. ZIP tato vlastnická oprávnění nenahrazuje.
2. Použít adresář `zdrojovy-kod`, Node.js 24 a npm. Přesné verze závislostí
   určuje `package-lock.json`; instalovat příkazem `npm ci`, ne aktualizací balíčků.
3. Zkopírovat `nastaveni-prostredi.example` do `zdrojovy-kod/.env.local`.
   Doplnit publishable/anon klíč z původního Supabase projektu.
4. Spustit `node --test tests/*.test.mjs`, `npm run build` a `npm start`.
   Pro vývoj je určen `npm run dev`. Aplikace se současným backendem používá
   stejné uživatele, databázi i loga jako nasazený Pivník.
5. Pro hostování připojit projekt k Vercelu, nastavit dvě proměnné NEXT_PUBLIC
   a doménu. Pro PWA je potřeba HTTPS. Ověřit URL v Supabase Auth a pozvánkách.

## B. Přesun do nového backendu

Tento ZIP je archiv kódu a logický export aplikační databáze. Není to úplná
binární záloha celého poskytovatele. Neobsahuje hashe uživatelských hesel,
Auth sessions, refresh/access tokeny, funkční zvací odkazy, databázové heslo,
service-role klíč ani tajná nastavení Vercelu/Supabase. V `struktura.json`
je seznam Auth identit (UUID, e-mail a metadata) pro mapování profilů.

Pro zachování původního přihlášení je nutná samostatná poskytovatelská záloha
Auth nebo oficiální úplný dump Supabase a příslušná nastavení šifrování,
pokud je původní projekt používá. Přihlašovací tajné hodnoty se mají přenášet
odděleně. Bez nich lze účty znovu vytvořit a nechat uživatele nastavit hesla;
jejich nová UUID musí být promítnuta do všech vazeb na uživatele.

1. Připravit nový Supabase projekt. Neprovádět obnovu přes živá produkční data.
2. Obnovit Auth účty původními UUID nebo připravit ověřené mapování nových UUID.
   Admin je v kódu i databázových pravidlech navázán na UUID
   `17be5dc3-a3f9-4fd2-ae90-dee7692034fc`.
3. Vybrat jednu cestu struktury: úplný oficiální dump, nebo přiloženou
   aktuální referenční rekonstrukci. Nesčítat tuto baseline s historickými
   migracemi. Historické migrace nejsou úplnou počáteční definicí databáze.
4. S PostgreSQL/psql použít referenční soubory v pořadí:
   `01-struktura-reference.sql`, `02-data-reference.sql`,
   `03-vazby-opravneni-reference.sql`. Spouštět s ON_ERROR_STOP a jako jednu
   transakci. Každá chyba musí obnovu zastavit. Skripty obsahují 54 tabulek dat,
   23 funkcí, omezení, indexy, triggery, RLS a explicitní oprávnění. První skript
   vytvoří navíc prázdnou tabulku pro pozvánky. Jejich staré přístupy se neobnovují.
   Jde o čitelnou rekonstrukci z katalogu PostgreSQL, nikoli pg_dump.
   Syntaxe je ověřena parserem; skutečný obnovovací běh v novém projektu nebyl
   v rámci této archivace proveden. Vyžaduje kontrolu vývojářem a test obnovy.
   Původní default ACL, vlastníci a přírůstky sekvencí jsou rovněž v JSON exportu.
5. Obnovit veřejný bucket `brewery-logos` s nastavením ze storage inventáře.
   Nahrát všech 50 souborů z `grafika-storage/brewery-logos` se stejnými cestami
   přes Storage API/UI. Nevkládat samotné řádky storage.objects jako náhradu souborů.
   Při změně projektu přepsat příslušnou část veřejných URL log v aplikačních datech.
6. Nasadit tři Edge Functions ze `zdrojovy-kod/supabase/functions`:
   `admin-invitations`, `redeem-invitation`, `complete-initial-password`.
   V `serverove-funkce` je i export skutečně nasazených funkcí a jejich konfigurace.
   Obnovit backendové SUPABASE_* hodnoty a nastavit `PIVNIK_SITE_URL` na novou URL.
   Kódy mají vlastní ověřování přihlášení; zachovat exportovanou konfiguraci verify_jwt.
7. Zkontrolovat Auth Site URL, redirect URL, e-mailové nastavení a přístupy správců.
   Tyto poskytovatelské hodnoty nejsou plně dostupné ze zdrojového repozitáře.
8. Ověřit počty tabulek a záznamů, integritu vztahů a oprávnění běžného uživatele.
   Spustit testy a produkční build. Vyzkoušet přihlášení, zápis/editaci ochutnávky,
   hodnocení, statistiky, pozvánku, ocenění a instalaci z Androidu/iPhonu.

## C. Historie a další práce

`historie-repozitare.bundle` obsahuje historii dosažitelnou z produkčního HEAD.
Obnovení lokálního Git repozitáře:

    git clone historie-repozitare.bundle pivnik-obnova

Pokud se po klonování otevře detached HEAD, vytvořit pracovní větev
`git switch -c main`. Samotný bundle neobsahuje GitHub issues, secrets, nastavení
Vercelu, přístupová oprávnění nebo případné jiné větve mimo tento HEAD.

`SHA256SUMS.txt` ověřuje všechny soubory v balíku kromě sebe samého.
`manifest-archivu.json` popisuje rozsah a hranice exportu. Záloha vznikla
čtením; produkční kód, databáze ani uživatelská data nebyly změněny.

Výchozí stav je považován uživatelem za hotový. Další práce má vycházet z
uživatelských komentářů a oprav. Archiv obsahuje osobní data a importní historii;
je určen vlastníkovi aplikace, ne jako veřejný instalační balíček pro uživatele.
